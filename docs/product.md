# プロダクト要件定義書

## 1. プロダクトビジョン

**Hono RPC × Next.js 15 フルスタック Kanban アプリ** は、フルスタック TypeScript による型安全な開発体験を実現する、最小限の依存関係で保守性の高いインタラクティブ・タスクボード（カンバンアプリ）です。

### ターゲットユーザー
- フルスタック TypeScript 開発を学習・実践したいエンジニア
- 型安全な API 通信（Hono RPC）を体験したい開発者
- モダンな React エコシステム（Next.js 15 App Router, RSC, Server Actions, Conform, Zod）を採用したいチーム

### 課題・ニーズ
- フロントエンド・バックエンド間の型共有が煩雑で、実行時エラーが発生しやすい
- Server Components と Server Actions を組み合わせたモダンなデータフローを実装したい
- 過度な依存関係（認証、WebSocket、重い状態管理ライブラリ等）を避け、コア機能に集中したい

## 4. ユーザーストーリー・受け入れ条件

### US-001: タスクを作成する
**として** ユーザー  
**たい** カラムのフォームからタスクを作成する  
**そうすれば** 作業を可視化できる  

**受け入れ条件:**
- [ ] カラム下部の入力欄にタイトルを入力し「追加」を押すとタスクが作成される
- [ ] タイトルが空の場合、エラーメッセージが表示され作成されない
- [ ] 作成後、フォームがリセットされる
- [ ] 新規タスクが該当カラムの末尾に表示される

### US-002: タスクを移動する
**として** ユーザー  
**たい** タスクをドラッグ&ドロップで別カラムへ移動する  
**そうすれば** 進捗を直感的に更新できる  

**受け入れ条件:**
- [ ] タスクカードをドラッグ開始するとゴーストイメージが表示される
- [ ] 別カラム上でドロップすると移動リクエストが送信される (Server Action)
- [ ] 移動完了までサーバー処理待ち（楽観的 UI は未実装）
- [ ] サーバー同期失敗時はエラー表示（将来拡張でロールバック対応）

### US-003: タスクを編集する
**として** ユーザー  
**たい** タスクタイトルをクリックしてインライン編集する  
**そうすれば** 詳細を素早く修正できる  

**受け入れ条件:**
- [ ] タスクタイトルをクリックすると編集フォームに切り替わる
- [ ] タイトル・説明を編集し「保存」で更新される (Server Action)
- [ ] 「閉じる」で編集キャンセル・元の表示に戻る
- [ ] タイトル空欄で保存するとバリデーションエラー表示

### US-004: タスクを削除する
**として** ユーザー  
**たい** タスクの × ボタンで削除する  
**そうすれば** 完了・不要な作業を除外できる  

**受け入れ条件:**
- [ ] × ボタン押下で削除リクエスト送信 (Server Action)
- [ ] 削除完了後、手動リロードで反映確認（楽観的 UI 未実装）
- [ ] 削除失敗時のエラー表示

### US-005: ボードを表示する
**として** ユーザー  
**たい** アプリ起動時に 3 カラムと既存タスクを一覧表示する (RSC)  
**そうすれば** 現在の進捗を把握できる  

**受け入れ条件:**
- [ ] 初回アクセス時にシードデータ（3 カラム）が表示される
- [ ] 既存タスクが正しいカラム・順序で表示される
- [ ] カラムヘッダーにタスク数バッジが表示される

## 5. 機能要件・非機能要件

### 機能要件
| ID | 要件 | 詳細 |
|----|------|------|
| FR-001 | REST API 提供 | GET /api/board, POST /api/tasks, PATCH /api/tasks/move, PUT /api/tasks/update, DELETE /api/tasks/:id |
| FR-002 | 型安全な RPC クライアント | `hc<AppType>` によるフロントエンド型推論 |
| FR-003 | 共有スキーマパッケージ | `@my-app/shared` で Zod スキーマを再エクスポート |
| FR-004 | データベースシード | 起動時に 3 カラム（Todo/In Progress/Done）を自動作成 (`upsert`) |
| FR-005 | Server Actions | `'use server'` 関数でフォーム処理、RPC 経由でバックエンド呼び出し |
| FR-006 | React Server Components | `page.tsx` で初期データ取得、Client Components に props 渡し |

### 非機能要件
| ID | 要件 | 目標値 |
|----|------|--------|
| NFR-001 | 型安全性 | コンパイル時・実行時ともに型エラー 0 件 |
| NFR-002 | 開発サーバー起動時間 | `pnpm dev` で 15 秒以内に両サーバー起動 |
| NFR-003 | テスト実行時間 | 全テスト `pnpm test` で 60 秒以内 (E2E 除く) |
| NFR-004 | バンドルサイズ | フロントエンド本番ビルド適切なサイズ |
| NFR-005 | アクセシビリティ | キーボード操作・ARIA 対応（最低限） |

## 6. 成功の定義

以下すべてを満たすことを「完了」と定義する：

- [ ] `pnpm dev` でバックエンド（:3001）・フロントエンド（:3000）が同時起動し、ブラウザでボードが表示される
- [ ] 全機能（CRUD、Drag & Drop、インライン編集）が手動テストで動作する
- [ ] `pnpm test` で全パッケージ（shared, backend, frontend）のテストがパスする
- [ ] `pnpm test:e2e` で主要フローがパスする
- [ ] TypeScript コンパイルエラーが 0 件（`tsc --noEmit`）
- [ ] 設計ドキュメント（`docs/` 配下）が実装と同期している
- [ ] Git コミット履歴が Conventional Commits 形式に準拠している
