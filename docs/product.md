# プロダクト要件定義書

## 1. プロダクトビジョン

**Hono RPC × Next.js 15 フルスタック Kanban アプリ** は、フルスタック TypeScript による型安全な開発体験を実現する、最小限の依存関係で保守性の高いインタラクティブ・タスクボード（カンバンアプリ）です。

### ターゲットユーザー
- フルスタック TypeScript 開発を学習・実践したいエンジニア
- 型安全な API 通信（Hono RPC）を体験したい開発者
- モダンな React エコシステム（Next.js 15 App Router, RSC, Server Actions, Conform, Zod）を採用したいチーム

### 課題・ニーズ
- フロントエンド・バックエンド間の型共有が煩雑で、実行時エラーが発生しやすい
- Server Components と Server Actions を組み合わせたモダンなデータフローを実装したい
- 過度な依存関係（認証、WebSocket、重い状態管理ライブラリ等）を避け、コア機能に集中したい

## 2. アクター定義

システムの外部境界に関わるアクターを定義する。各アクターが実行できる操作は [`docs/usecases.md`](usecases.md) のユースケースにマッピングされる。

| アクター ID | 名称 | 種別 | 説明 |
|-------------|------|------|------|
| ACT-001 | ユーザー | 主アクター | ボードを閲覧し、タスクの作成・移動・編集・削除を行う。認証はなし（全員が同一ユーザー扱い） |
| ACT-002 | システム（バックエンド起動処理） | 間接アクター | スプリント作成時に 3 カラムをトランザクションで自動生成する（`apps/backend/src/index.ts`）。ユーザー操作を伴わない |

### システム境界

| 境界内 | 境界外（スコープ外） |
|--------|---------------------|
| スプリント単位の複数ボード管理 | 認証・認可（BR-006） |
| SQLite 永続化 | リアルタイム同期 / WebSocket（BR-007） |
| 型安全 RPC 通信 | スプリントの状態管理・期限超過判定・ベロシティ |

## 4. ビジネス要件

| ID | 要件 | 背景・目的 | 優先度 |
|----|------|-----------|--------|
| BR-001 | pnpm ワークスペースによるモノレポ構成 | フロント・バック・共有パッケージの型とスキーマを単一リポジトリで同期管理するため | 必須 |
| BR-002 | Hono RPC による End-to-End 型安全性 | フロント・バック間の型共有の煩雑さと実行時エラーを解消するため（課題 1） | 必須 |
| BR-003 | Next.js 15 App Router (RSC + Server Actions) 採用 | モダンなサーバーファーストのデータフローを実践するため（課題 2） | 必須 |
| BR-004 | SQLite (better-sqlite3) + Prisma ORM での永続化 | セットアップ不要で軽量な永続化を実現するため | 必須 |
| BR-005 | インラインスタイルのみ（CSS ファイル・Tailwind 非使用） | ビルド不要・最小依存でコア機能に集中するため（課題 3） | 必須 |
| BR-006 | 認証・認可機能はスコープ外 | 型安全通信と CRUD のコア体験に集中するため | 除外 |
| BR-007 | リアルタイム同期（WebSocket）はスコープ外 | 依存を最小限に保つため | 除外 |
| BR-008 | スプリント単位の複数ボード対応 | スプリントごとに独立したカンバンボードを管理するため | 必須 |

## 6. 機能要件・非機能要件

### 機能要件
| ID | 要件 | 詳細 |
|----|------|------|
| FR-001 | REST API 提供 | 全エンドポイントの仕様は [`docs/api.md`](api.md)（唯一の正本）を参照 |
| FR-002 | 型安全な RPC クライアント | `hc<AppType>` によるフロントエンド型推論 |
| FR-003 | 共有スキーマパッケージ | `@my-app/shared` で Zod スキーマを再エクスポート |
| FR-004 | スプリント作成時カラム生成 | スプリント作成時に 3 カラム（Todo/In Progress/Done）をトランザクション生成 (`apps/backend/src/index.ts`) |
| FR-005 | Server Actions | `'use server'` 関数でフォーム処理、RPC 経由でバックエンド呼び出し |
| FR-006 | React Server Components | `page.tsx` で初期データ取得、Client Components に props 渡し |

### 非機能要件
| ID | 要件 | 目標値 |
|----|------|--------|
| NFR-001 | 型安全性 | コンパイル時・実行時ともに型エラー 0 件 |
| NFR-002 | 開発サーバー起動時間 | `pnpm dev` で 15 秒以内に両サーバー起動 |
| NFR-003 | テスト実行時間 | 全テスト `pnpm test` で 60 秒以内 (E2E 除く) |
| NFR-004 | バンドルサイズ | フロントエンド本番ビルド適切なサイズ |
| NFR-005 | アクセシビリティ | キーボード操作・ARIA 対応（最低限） |

## 7. 成功の定義

以下すべてを満たすことを「完了」と定義する：

- [ ] `pnpm dev` でバックエンド（:3001）・フロントエンド（:3000）が同時起動し、ブラウザでボードが表示される
- [ ] 全機能（CRUD、Drag & Drop、インライン編集）が手動テストで動作する
- [ ] `pnpm test` で全パッケージ（shared, backend, frontend）のテストがパスする
- [ ] `pnpm test:e2e` で主要フローがパスする
- [ ] TypeScript コンパイルエラーが 0 件（`tsc --noEmit`）
- [ ] 設計ドキュメント（`docs/` 配下）が実装と同期している
- [ ] Git コミット履歴が Conventional Commits 形式に準拠している
